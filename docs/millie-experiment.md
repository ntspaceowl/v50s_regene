# 밀리의서재 독서 실험 (2026-10-06)

시작 설치본은 kr.co.millie.millieshelf 5.47.0.0/code6404이다. 열린 화면은 kotlin.ui.viewer.pdf.ui.PdfViewerActivity. 해당 뷰어는 SECURE 창이어서 캡처가 보호되며, 초기 ADB 캡처 파일은 비어 있었다. 보호를 해제하지 않는다.

사용자는 ‘가로 모드 두 쪽 보기’ 옵션이 있고 켜둔 상태라고 확인했다. ReGene 0.1.17/code18 시험본에 좌우 독서 프로필을 추가했다. 기존 에뮬레이터는 가로, 독서는 세로 자세에서 확장한다. 런처에서 밀리의서재를 선택했을 때 이미 열려 있던 PDF로 복귀했고 제어 서비스가 해당 뷰어를 인식했다.

LG 확장 요청 1회 뒤 DocumentView는 2160×2340, Android Activity 구성은 w822dp/h814dp, land, ROTATION_0였다. 즉 물리 기기는 세로이며 뷰어는 사용할 수 있는 가로 폭에 따라 가로 모드를 인식했다. PdfFragment의 자체 설정은 layoutMode=DOUBLE, isFirstPageAlwaysSingle=true였다. 이 정보는 설정과 논리 배치 확인이며 실제 두 패널에 페이지 한 장씩 보이는지에 대한 최종 증거는 아니다.

초기 단독 페이지는 x318..1841/y0..2340에 위치했다. 첫 표지를 단독 표시하는 설정 때문일 수 있다. 다음 펼침의 좌우 배치, 글/그림의 힌지 침범 여부 및 실제 손가락 페이지 넘김을 한 묶음으로 요청했고, 사용자는 ‘좌우 한 페이지씩 나오고 넘기기도 잘돼’라고 확인했다. 별도 사진/픽셀 검사가 아니라 사용자의 실제 패널 관찰이다. 코드가 실제 책 내용을 읽거나 저장하지 않았다.

`app/test.ps1`의 기존 회귀 시험과 ContentProfileTest, 전체 빌드 및 APK v2/v3 서명 검증이 통과했다. 기존 게임 프로필/배치/컨트롤러 설정은 바꾸지 않았다.

HOME 입력 뒤 restore_pending=false, 본체 논리 크기1080×2340, 본체 런처 전경 및 대기 상태를 확인했다. 최종 빌드를 다시 설치한 뒤 ReGene 독서 버튼으로 동일 PDF에 복귀했고 2160×2340, layoutMode=DOUBLE, 확장 요청1회를 확인했다. 최종 APK SHA256은 F2114943AB30D9D5690A27C49CAA2265BDDEBCD5164765F80A08EA17FEDEB2A8이며 설치된 APK와 배포 파일의 해시가 같다.

EPUB 동작, 다른 PDF 책의 페이지 형상, 이번 독서 프로필의 커버 닫기/열기 및 실제 자세 전환은 아직 실기기 통과로 기록하지 않는다. 회전 프로필의 자동 판정은 순수 Java 테스트를 통과했다. 사용자에게 이미 확인한 페이지 시험을 다시 요청하지 않는다. 최종 기기는 책 뷰어에서 독서 확장을 켠 상태이며 auto_pose=true다.

## 0.1.19 실행 세션 후속

HOME/다른 앱 전환으로 독서 세션을 끝내도록 변경했다. ReGene 실행에서 2160×2340 확장을 확인하고 HOME 이후 앱의 실제 런처 Activity로 직접 실행하여 1080×2340, controller_running=false, restore_pending=false를 확인했다. 이전 버전의 자동 복귀 재개 기록을 대체한다. 앱의 두 쪽 보기 설정과 책 데이터는 유지한다. 상세는 [독서 세션 검증](reading-session.md)을 따른다.
