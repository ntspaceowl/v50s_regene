# V50S ReGene 자동 듀얼스크린 제어 설계 제안

상태: 사용자 승인 후 ReGene 초기 버전 구현 및 실기기 시험 중. 아래 초기 증거는 당시의 검토 기록이며 최신 결과는 README와 시험 로그를 참조한다.

## 목표와 완료 기준

V50S에서 Citra, melonDS, DraStic, Azahar를 실행하고 기기를 가로로 돌리면 듀얼스크린에는 게임 상단 화면, 본체에는 게임 하단 터치 화면과 모든 게임 조작 버튼이 표시되어야 한다. 홈 복귀, 게임/설정 화면 전환, 화면 꺼짐/켜짐, 커버 연결 해제/재연결 이후에도 수동 WideMode 실행 없이 복구되어야 한다. 화면 비율과 터치 좌표를 보존한다. 초기 권한 설정 이후 PC 연결이 필요 없어야 한다.

## 추가 요구사항: 외부 컨트롤러와 가상패드 (2026-10-04)

사용자 요청: 모든 지원 에뮬레이터에서 블루투스 또는 USB-C 컨트롤러가 연결되면 화면에 표시되는 가상패드를 자동으로 모두 숨긴다.

- 대상: Citra, melonDS, DraStic, Azahar. 방향키, 스틱, ABXY, 숄더, START/SELECT와 가상패드의 부가 버튼까지 포함한다. 매핑된 버튼만 숨기는 동작은 이 요구사항을 충족하지 않는다.
- 게임의 하단 터치 화면은 계속 표시하고 터치 입력을 유지한다. 상단/하단 화면 배치와 게임 진행도 유지한다.
- 실행 전 이미 연결된 컨트롤러와 게임 중 연결 모두 처리한다. 블루투스와 USB-C는 같은 동작으로 취급한다.
- 마지막 컨트롤러가 분리되면 연결 전 가상패드 표시 설정으로 복원한다. 사용자가 원래 숨겨 둔 가상패드를 임의로 표시하지 않는다. 여러 컨트롤러 중 하나만 분리되면 계속 숨긴다.
- 구현 순서: 에뮬레이터 자체 자동 숨김 설정을 먼저 검증한다. 기능이 없거나 일부 버튼만 숨기는 경우에는 해당 앱의 제어 경로를 별도로 검토한다. 제어 앱의 장치 연결 감지만으로 다른 앱의 가상패드를 숨겼다고 판단하지 않는다.
- 추가 검증: 네 앱 각각에서 실행 전 연결, 게임 중 연결/분리, HOME 복귀, 하단 터치 유지, 버튼 전체 숨김, 기존 수동 표시 설정 복원을 확인한다. 실제 블루투스/USB-C 연결 시험이 완료되기 전에는 구현 완료로 기록하지 않는다.

현재 상태: 요구사항 확정, 제어 경로 조사 중. 자동 숨김 구현/실기기 검증 미완료.

## 비교한 방법

1. 권장: 별도 자동 제어 앱에서 LG의 화면 확장 API를 직접 호출하고 에뮬레이터의 기존 레이아웃 설정을 이용한다. 앱 화면을 끼워 넣지 않고 백그라운드에서 동작시켜 세로 전환을 피한다. 에뮬레이터 업데이트와 제어 앱을 분리할 수 있다. LG/에뮬레이터의 실제 동작 검증이 필요하며 Azahar에는 추가 충돌 해결이 필요하다.
2. 화면 캡처를 잘라 커버에 표시하는 별도 앱: 원본 게임 수정은 줄지만 캡처 권한, 지연, 터치 전달 문제가 생긴다. 현재 결과로는 채택하지 않는다.
3. 각 에뮬레이터에 직접 듀얼 디스플레이 출력을 추가: 화면/터치를 가장 정확하게 제어할 수 있지만 포크 유지 부담이 크다. 별도 앱으로 해결되지 않는 충돌만 최소 수정 또는 upstream 개선 대상으로 검토한다.

## 구성과 동작

- 작은 Android 네이티브 제어 앱과 백그라운드 서비스. 실행할 에뮬레이터별 프로필, 자동 동작 스위치, 상태와 오류 확인 화면을 제공한다.
- 전경 앱/게임 Activity 전환, 기기 자세, 실제 커버 표시 상태를 감지한다. 앱 감지에 Usage Access 또는 접근성 권한 중 실제 기기에서 필요한 최소 경로를 선택한다. 자세는 센서로 감지하여 회전 잠금과 독립적으로 추적한다.
- 지원 게임 화면이 전경이고 커버가 연결되어 있으며 가로 자세이면: 올바른 방향(rotation3)을 확보한 뒤 LG 확장 API를 직접 호출한다. 세로 강제 Activity를 띄우는 기존 WideMode 아이콘 경로는 사용하지 않는다.
- 확장 상태와 실제 논리 화면 크기, 방향을 읽어 성공 여부를 확인한다. resize/game Activity 전환 이후 한정된 재시도로 복구한다. 실패 상태에서 무한 호출하지 않는다.
- 홈 또는 대상 앱 종료, 세로 자세, 커버 분리 시 확장을 해제하고 앱 활성화 전의 시스템 회전 설정을 복원한다.
- Citra/DS 에뮬레이터의 저장된 상하 레이아웃을 사용한다. 일회성 프로필 설정은 앱별로 안내하고 백업한다. ROM/세이브를 제어 앱이 수정하지 않는다.
- 필요한 특권이 있다면 초기 설정에서 명확히 표시하고 검증한다. WRITE_SETTINGS만으로 앱 방향 요청을 이길 수 있는지는 아직 미확인이다. DraStic에서 사용한 ADB ignoreOrientationRequest를 앱이 재현할 수 있는지 우선 검증한다. PC를 상시 필요한 상태는 완료로 인정하지 않는다.

## 현재 증거와 미해결점

- Citra: 빠른 설정 WideMode 경로는 가로 방향 유지, 상하 배치, 정확한 하단 터치, 홈 복귀 후 수동 복원을 통과했다. 기존 Activity 경로에서는180픽셀 Y 오차가 재현됐다. 직접 API 호출이 빠른 설정 경로와 같은 결과를 내는지 앱에서 검증해야 한다.
- DraStic: 전용 HeartGold 레이아웃과 모든 게임 버튼의 본체 배치를 저장했고 재실행 때 유지됨을 확인했다. 과거 Activity 기반 확장/회전에서 일시적인 거꾸로 된 프레임이 관찰되어 빠른 설정 경로를 비교 중이다.
- melonDS: 전용 HeartGold 레이아웃과 하단 게임 터치 입력을 확인했다. 모든 버튼 배치와 자동 복원 검증은 남았다.
- Azahar: OFF 상태의 가상 HiddenDisplay가 LG 시스템의 확장 해제 경로를 일으킨다. 단순 재시도만으로 안정화됐다고 판단하지 않는다. 이 충돌의 해결은 전체 완료 조건에 포함하며, 별도 앱만으로 해결할 수 없으면 최소 upstream 수정안을 별도로 제시한다.
- 커버가 Android Presentation용 디스플레이로 인정되지 않아 기본 외부 화면 설정만으로는 현재 목표를 달성하지 못했다.
- ADB 입력과 디스플레이 매핑 외에 사용자의 실제 패널/손가락 입력 확인도 필요하다.

## 검증

각 에뮬레이터마다 시작 -> 가로 회전 -> 두 화면/비율/하단 터치/동시 게임 버튼 입력 -> HOME/복귀 -> 게임/설정 화면 전환 -> 세로/가로 재회전 -> 화면 꺼짐/켜짐 -> 커버 분리/재연결을 검증한다. 최초 설정 후 USB를 분리한 상태에서도 자동 동작을 확인한다. 각 앱의 문제를 해결하거나 명시적으로 미완료로 남기며 다른 앱의 성공으로 대신하지 않는다.

## 승인된 실행 흐름 (2026-10-04)
사용자: 자동제어앱 이견없음. 제어앱을 켜고 에뮬레이터를 선택하면 맞춰 실행되는 흐름 승인.
설계 상태: 승인됨. 런처에서 네 앱을 선택하고 권한 설정을 한 번 수행. 게임 화면 전환 이후 백그라운드에서 확장을 적용하고 홈에서는 복원한다.
