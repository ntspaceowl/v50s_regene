# 코드 리뷰와 정리 (2026-10-05)

ReGene 런처, 제어 서비스, LG 확장/방향 제어, Citra 접근성 자동화, 빌드 스크립트, Azahar·melonDS의 현재 적용 패치를 리뷰했다. 통과한 게임 배치, 입력 매핑과 전역 해상도 설정은 변경하지 않았다.

## 발견과 수정

| 문제 | 영향 | 수정 |
|---|---|---|
| 종료/유휴/이전 세션 복구에서 LG API 오류가 뒤의 정리를 건너뜀 | 확장 해제 실패 시 방향 유지 창과 회전 설정도 남을 수 있음 | `ReleaseActions`로 각 정리를 독립 실행하고 오류를 함께 보고. 회전 저장 실패 시 설정을 바꾸지 않으며 복원 실패 시 복원 기록을 유지 |
| APK 업데이트 뒤 저장된 `controller_running=true`만 남음 | 실제 제어 서비스가 없는 상태에서도 Citra 접근성 자동화가 세션으로 오인할 수 있음 | 동일 프로세스의 실제 서비스 실행 상태로 자동화 조건 판단. 런처가 오래된 표시 상태 정리 |
| 빌드가 이전 `.class`와 dex 출력을 재사용 | 삭제/이동한 클래스가 새 APK에 잔류 가능 | 재빌드 전 해당 출력 디렉터리만 비움. 서명 키는 보존 |
| Citra surfaceChanged 레지스터 증설이 CRLF만 처리 | LF로 디코드되면 주입 코드의 v0 레지스터를 확보하지 못함 | 줄바꿈에 독립적인 치환과 정확히 한 선언 확인 |

## 검증

- `app/test.ps1`: Citra 대상/복원 기록 분리, 전경 이벤트 중복 처리, 회전 히스테리시스, 종료 실패 격리, Citra LF/CRLF 레지스터 처리 모두 통과.
- 종료 회귀 시험은 LG 확장과 창 제거에 각각 예외를 주입해도 회전 복원이 실행되고 두 오류가 보존되는지 검사했다. LG 장치 API 오류를 실제 폰에서 강제로 발생시킨 시험은 아니다.
- 삭제된 클래스에 해당하는 임시 `.class`를 빌드 폴더에 넣은 뒤 실제 재빌드하여 잔류하지 않는지 확인했다.
- ReGene 0.1.16/code17 전체 빌드, APK v2/v3 서명 검증, V50S 업데이트 설치 통과.
- 설치 후 실제 제어 서비스가 없는 상태에서 런처의 `controller_running=false`, Citra 버튼을 통한 전경 서비스 시작을 확인했다. 종료 버튼의 서비스 종료 및 복원 기록 상태도 확인했다.
- 현재 ReGene APK SHA256: `112DCB2A32B5DA096ED40BB8FD7E1738D8CFA9401E88B8E1A24227E8E842371E`. 설치된 APK와 최종 배포 파일의 해시 일치를 확인했다.

전체 네 앱의 물리 배치/회전/터치/BT/커버 개폐는 기존 사용자 통과 기록을 따른다. 이번 리뷰에서 그 시험을 다시 한 것으로 기록하지 않는다. 최신 기능 완료 근거는 `completion-audit-2026-10-05.md`, 후속 코드/설치 상태는 이 문서다.

## 중복 Citra와 부산물 정리

폴더 안의 아이콘은 단순 중복 바로가기가 아니라 `com.antutu.ABenchMark`라는 패키지 이름의 오래된 Citra였다. 실행 Activity가 `org.citra.emu.ui.MainActivity`인 것을 확인하고 `pm uninstall -k --user 0`으로 앱만 제거했다. 패키지 데이터와 `/sdcard/citra-emu`는 보존했다. 실사용 Citra `org.citra.rgn`은 유지하며 현재 런처 활동 목록에도 이 Citra만 남았다.

82개 경로, 25,381개 파일, 합계 2,263.3 MiB의 작업 부산물을 휴지통으로 옮겼다. 세부 목록은 로컬 `backups/2026-10-04/cleanup-2026-10-05.csv`에 보관했다. 이후 최종 검증에서 다시 생성된 빌드 출력과 캡처도 정리했다.

소스·패치·서명 키·최종 APK 4개·복구용 백업·원본 빌드 입력은 보존한다. 휴대폰 ROM과 세이브 및 이번 작업과 관계없는 앱은 정리 대상에서 제외했다. 재빌드 기준과 현재 적용/과거 후보 패치 구분은 `build-inputs.md`에 기록했다.
